# Progress 2026-11-13

## CUSUM change-detector baseline (plan §6)

**Change.** `src/hotwell_bench/cusum.py`, `scripts/cusum_baseline.py`,
`tests/test_cusum.py`; README entry-point row and a CUSUM paragraph replacing "Not yet
provided". Grader and packaged data unchanged.

**Method (from the module docstring).**
- 1-minute means and log standard deviations of the 1 Hz record. The 18 non-pump
  instruments are used as they are; each pump pair is folded into running-pump current,
  running-pump NPSH margin and standby-pump NPSH margin (running pump = larger current),
  with ±5 min around swaps held. 48 features.
- Load L = median of five proxies (mw_out, steam_flow, condensate_flow, firing_rate,
  throttle_pos), each mapped to MW by a linear fit. Each feature regressed on
  [1, L, L², ΔL over 10 min, ΔL over 30 min] over fault-free training minutes;
  residual / (1.4826 MAD).
- Two-sided CUSUM, k = 1; threshold per feature and side = 1.25 × the training maximum,
  floor 5. Onset = start of the run that crossed.
- Category: nearest dev fault item by signature (direction of each feature's first
  crossing within 120 min, plus the first feature). Instrument faults name the raw
  instrument behind the first feature; pump faults name the running pump.
- Training: the dev split only (9 null days + the part of every fault day before
  t_inj − 1 min; 40 detected dev faults as signatures). The eval split's keys are never
  read by the script.

**Reading.** Plan §6: "If the change detector solves most items, the set is too easy."
A simple detector trained on 50 dev items gets two thirds of test fully right. Most
physical-fault items reduce to "find the one change in a near-stationary day, look up
its signature". Where it fails: instrument faults (0.167) and stuck actuators (0.296),
and 8 of 39 null days raise a false alarm.

**Test.** `pytest tests/test_cusum.py -s` → `2 passed`; prints
`alarms on training days: 0/30; on unseen fault-free days: 3/10 […]` and
`step 0.05 (5 sigma) at minute 45: alarm minute 45, onset minute 45, first feature
da_pressure:mean`. The first version of the test asserted zero alarms on unseen days
and failed (4/4 alarmed with 8 short training days). Diagnosis: a multiple-comparison
effect of the threshold rule (96 one-sided statistics per minute against thresholds
from finite training maxima), the same mechanism as the 8/39 on test. The algorithm
was NOT changed, because the test-split result was already in hand and any change now
would be tuning on test. The test now asserts what the method promises (silence on
its training days, detection and onset of a clear step) and prints the unseen-day
false-alarm count; the module docstring states the weakness.

**Generator finding (for 0.2).** One test item with a sensor `lag` fault was missed by
every method. hotwell applies the lag to the true value before adding sensor noise, so
on a white-noise instrument the noise is unchanged (first-difference σ 0.0336 before,
0.0340 after) and the fault shows only as a few-second delay during a fast transient
(here a pump stopping). The twin-diff label sees it; an analyst without the twin
practically cannot. Lag faults need a visibility criterion beyond a single transient.
