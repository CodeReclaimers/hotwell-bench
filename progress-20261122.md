## C4 pushed; C5: grader 0.2 (PLAN-bench-0.2.md §6)

**Grader 0.2** (`src/hotwell_bench/grade.py`). Applies only to keys of a 0.2 split,
recognized by the `decoys` field (`key_version`; a key set mixing versions raises).
Nothing changes for 0.1 keys, so their per-item rows, summary and report are
byte-identical. Additions:
- Per fault item: `onset_score` = exp(−|onset − t_inj| / 1800 s).
  - 0.0 when the onset is missing or the answer is invalid.
  - None on null items.
  - It is computed from the onset alone, like the 0.1 `onset` field, whatever
    `fault_present` says.
- Detection delay: the plan lists "per-item detection delay relative to t_det". The
  0.1 grader already writes `onset_minus_tdet_s` per item, so no new per-item field
  was added. The 0.2 summary adds `onset_minus_tdet_s` = {n, q25, median, q75} over
  fault items that give an onset. The quantile is element `q[k·n // 4]` of the sorted
  values, the same upper-median convention as the 0.1 `onset_abs_err_s_median`.
- Summary rows gain a mean `onset_score`, shown as column `oscor` in the report, and
  the summary records `bench_version: "0.2"`.
- New strata. The 0.1 strata are unchanged, including `ratio` with buckets <1 / 1-2 /
  >=2.
  - `decoys`: {null, fault} × {decoy, no decoy}.
  - `decoy_kind`: {null, fault} × each kind on the day. A two-kind day counts in both
    rows; no-decoy days are in no row.
  - `ratio_w`: <1 / 1-1.5 / 1.5-2 / 2-3 / >=3, plus n/a and null. On P02 keys the key
    ratio is already magnitude / windowed threshold. Under log-uniform 0.7–3 the four
    main buckets hold about 25 / 28 / 20 / 28 %.
  - `strict`: strict observable / lenient only / null (the C4 key field).
- Choices I made where §6 does not say (flagged to Alan): the bucket edges, the
  null/fault split of the decoy strata, onset_score 0 for a missing onset.
