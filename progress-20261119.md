**Files:** `PLAN-bench-0.2.md` (new).

**Key decisions (plan §10):**
- **Task format unchanged.** Same task format, answer schema and `task.md` category list,
  so a 0.1 harness runs 0.2 unchanged and a score change measures difficulty alone.
- **Labelling first.** A windowed level rule (W = 600 s, S = 60 s) with a threshold from
  seed-pair fault-free days, targeting a ≤ 1% per-day false-positive rate.
  - Rejected: a sensor-noise-only threshold. It ignores load-driven variation, so it
    would label faults as observable that no practical method can find.
- **Sensor `lag` faults dropped from 0.2.** A lag fault shows only in transients.
  - Deferred: a three-transient visibility criterion.
  - Rejected: longer lag time constants, which are still invisible at steady state.
- **Category exclusions kept:** makeup-valve faults and `actuator_sluggish`.
- **Decoys bench-only:** load excursions, odd-time pump swaps, trim bursts.
  - hotwell stays at 0.4.0.
  - Deferred: decoys that need new hotwell procedures (soot blowing, setpoint changes,
    backwash, calibration checks).
- **No misleading operator notes in 0.2.** True explanatory notes only, where a decoy is
  not already explained by the logs.
- **`P_NULL` = 0.30, fixed** (agreed range 25–30%). Not a calibration knob, because it
  changes the score's composition rather than item difficulty.
- **Splits:** dev 50, test 200 (attempt-cap exclusions are not backfilled).
- **Calibration:**
  - only generation knobs move, never items;
  - dev only, at most 3 rounds;
  - two probe models under a spend cap, recorded with the runner, outside this repo.
- **How the §0 target is checked:** one strongest-model dev run in the last round, outside
  the probe cap (B2-Q9).
  - Rejected: a probe-model score band;
  - rejected: checking only after freeze, when nothing can be tuned.
