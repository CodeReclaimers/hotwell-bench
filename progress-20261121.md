# Progress 2026-11-21

## C1.4: replay-mode null pairs (Alan's choice after the C1.3 diagnosis)

**Decision (Alan):** rebuild the null pairs so that run B replays run A's recorded
operator actions with a different seed. This is the twin's semantics, so A − B
contains no operator-timing difference, matching the F − T the rule tests.

**Alternatives offered and rejected:**
- Masking swap windows in the existing data: trim-timing differences stay in, and
  the validation half had been looked at.
- A separate multiplier for the pump group: ad hoc.

**Change.** `scripts/null_pairs.py --mode {independent,replay}` is required.
- `replay` runs `Drive(build(B), "twin", replay=A.actions)` up to A's end time.
- Replay runs are cached in `cache/null_pairs/replay/`, keyed by A, B, the environment
  and RUNNER_VERSION. They are not stored under run.py's `twin` key, whose meaning
  (replay of the same item's faulted run) would be wrong here.
- Output goes to `out/null_pairs/stats-<mode>.json`.
- The pair definition, the even/odd split, the statistic and the estimator
  (`window_thresholds.py`) are unchanged.

**Verification:**
- `--mode independent` recomputed from cache reproduces the C1.3 statistics:
  `independent mode reproduces earlier stats (except new 'mode' key): True`.
- `ruff check scripts/null_pairs.py` → `All checks passed!`

**Data caveat.** The A runs are the C1.3 ones; only the 200 B runs are new. The
odd-pair validation data seen in C1.3 was the independent A − B differences, used to
locate the swap tails. Nothing in the estimator was tuned on it.

**Running:** `null_pairs.py --pairs 0-199 --mode replay --workers 28` (200 runs).
