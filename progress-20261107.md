  `result()`. `run_built` is now a thin wrapper.

  the new event after the simulator's event pointer (`_event_idx`, read-only here).

## B3 step 2: labelling rules; G-B2 passed (19:40 EST)

**Changes.**
- `src/hotwell_bench/label.py`: per-instrument evidence from the faulted and twin runs,
  three rules:
  - level: |F − T| > D_i for 10 samples. Hotwell's rule and convention (time = first
    sample of the run).
  - stuck: a run of identical readings at least 2× and 60 samples longer than the twin's
    longest. The time is clamped to the instrument's first divergence.
  - variance: the rolling std ratio of first differences leaves [0.8, 1.25] for 60
    samples, window 600.

  `label_runs()` → Label:
  - t_det, rule, instrument, per-rule table;
  - first divergence;
  - operator divergence: the first shift-log difference, with `operator_mediated` if
    it is ≤ t_det;
  - easy = a protective trip or plant death not in the twin;
  - first new alarm, end time.
- `tests/test_b3_label.py`:
  - synthetic rule arithmetic, including a chance-length run that must not fire;
  - seeded simulator cases per rule, with nothing before onset;
  - a regression guard that the level rule alone misses stuck and noise;
  - **slow G-B2**.
- `scripts/gb2_sweep.py`: G-B2 with per-rule diagnostics.

**Bug found in my own first version of the new rules (before commit), via G-B2
diagnostics.**
- Symptom: "any run longer than the twin's longest" fired on faults hotwell finds
  undetectable. FRV −1 %, firing −0.2 %/−0.5 % and fouling +5 % all fired via
  `stuck/fp1_current@+175`; the leak 0.1 kg/s fired 514 s before the level rule.
- Diagnosis (`scripts/gb2_sweep.py`): every such hit was a run 1–3 samples longer than
  the twin's maximum (4 vs 3, 8 vs 7, 21 vs 16, at most 6 vs 3). A tiny truth
  perturbation re-quantizes the reading and reshuffles run lengths by chance. The
  120-sample variance window gave late isolated hits (firing_rate @+2425..2445).
- Fix: the stuck margin (≥ 2× and ≥ +60 samples) and the variance window 600 / sustain 60.
- After: every row hotwell finds undetectable shows `no stuck/variance hits`. The
  remaining variance hits are on rows with real dynamics changes: makeup starting to hunt
  for 1 and 3 kg/s leaks; FRV dither stopping when stuck (@+384); DA LCV stuck (@+619).
- Closing the class: G-B2 now *asserts* no rule fires on any hotwell-undetectable row.
  That is a check on all 16 such rows, not on the instances I saw.

## B3 step 3: confuser check; G-B3 passed (19:51 EST)

**Changes.** `src/hotwell_bench/confusers.py` and `tests/test_b3_confusers.py`.

**Candidate table (a priori), each in both directions:**
- running FP ↔ FRV;
- running CP ↔ DA LCV;
- firing_degrade ↔ firing_rate sensor bias/drift;
- condenser_fouling ↔ cond_pressure sensor bias/drift;
- actuator_stuck X ↔ stuck sensor on X's position instrument (no fit).

Standby-pump primaries get no candidate (no settled signature at onset).

**Method.**
- **Branching:** a twin snapshot at t_inj − 1 s; each trial branches with a validated
  confuser scenario.
- **Signature:** the instrument with the largest |mean(F − T)|/D_i over the fit
  window. The window starts 600 s after the ramp ends and lasts 1800 s, cut at the first
  scheduled swap inside it when ≥ 300 s remain.
- **Fit:** secant on the deviation, ≤ 6 evaluations, tolerance max(5 %, 0.25 D_i).
- **Verdict:** the confuser is run to the primary's end and compared with the primary
  by all three labelling rules (shared noise). It is confusable iff no rule fires and the
  end state is the same.

**G-B3 premise adjusted (flagged).** The plan's seeded confusion "FP-1 vs FRV with no swap"
holds only near threshold. At −3 % the FP-1 current falls 10 A against D = 3 A
(hotwell M5), which separates the pair 1 s after onset. The gate therefore has three cases:
- −0.5 %, no swap → confusable;
- −0.5 % with a swap → separable;
- −3 % → separable by current.

**Bug fixes in my own code before commit.**
- The verdict run used `until = t_end + 1`, one more sample than the primary. That would
  have made every pair "different end". Changed to `t_end`.
- The fit window straddled a swap in the G-B3 swap case (fitted shift 0.0089 vs 0.0132
  pre-swap). Now cut at the swap.
